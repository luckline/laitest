# 领测 LingTest 产品能力地图

## 产品定位

领测是面向测试工程师、质量负责人和研发团队的 AI 质量工作台。它把需求分析、测试设计、自动化验证、结果分析和测试资产沉淀连接为同一条可追溯工作流，而不是单一的“AI 生成用例”工具。

核心闭环：`需求 → 风险 → 覆盖 → 用例 → 执行 → 证据 → 复用`。

## 一级能力

### 1. 测试分析与设计

- 快速需求输入与文档驱动分析
- 需求完整性、一致性、歧义性与可测试性审查
- 代码 Diff 影响面分析
- 风险分级与测试深度规划
- Server、Web、客户端和灰度实验需求拆分
- 等价类、边界值、判定表、状态迁移、场景法、因果图和错误推测
- 结构化测试用例生成与评审
- 需求—用例追溯矩阵
- Excel、结构化 JSON 与 Case Home JSON 交付
- 登录用户生成记录云端保存与恢复

### 2. Web 自动化测试

- 从结构化用例识别可自动化场景
- Playwright 真实浏览器执行
- 基于角色、标签和可见文本的语义定位
- 文本、标题、URL 和可见性等明确断言
- 单用例与批量执行
- 步骤级状态、耗时与执行日志
- 失败截图与现场回溯
- 风控拦截、执行失败与人工确认结果区分
- 本地运行历史

### 3. API 自动化测试

- 按用户隔离的测试项目
- 多环境 Base URL、公共请求头和变量管理
- HTTP 方法、路径、查询参数、请求头、请求体和超时配置
- `{{variable}}` 动态变量替换
- 状态码、响应时间、响应头、文本包含、JSON Path 和 JSON 全量断言
- JSON 动态字段忽略
- 从 JSON 响应或响应头提取变量
- 套件顺序编排、上下文变量传递和失败停止
- 单接口调试、套件执行与历史报告
- 请求凭证脱敏、响应体限制和 SSRF 防护

### 4. 质量资产与辅助工具

- JSON 格式化与校验
- 文本 Diff
- 正则表达式测试
- Unix 时间戳转换
- Base64 编解码
- 测试方法库和实践指南
- 账户、免费额度、专业版权益与激活

## 信息架构

工作台保持三条清晰主线：

1. **测试分析与设计**：回答“测什么、为什么测、覆盖是否充分”。
2. **Web 自动化测试**：回答“用户界面上的关键路径是否真实可用”。
3. **API 自动化测试**：回答“服务接口与跨接口业务链路是否符合契约”。

测试报告、运行证据和生成记录分别保留在产生它们的工作流中，避免为了“功能集中”而制造额外导航层级。

## 专业边界

- 不将模型生成内容直接视为通过评审的测试资产。
- 不将完成点击或填写动作视为测试通过，必须存在明确断言。
- 不绕过验证码、网站风控或访问控制。
- 默认禁止接口执行器访问本机和内网地址。
- 不在报告中明文展示 Authorization、Cookie、API Key 等敏感请求头。
- 当前 Web 执行记录保存在浏览器本地；API 报告保存到登录账户。

## 后续演进优先级

### P0：可用性与可信度

- OpenAPI/cURL 导入
- 可视化请求参数与断言编辑器
- 环境密钥加密存储和变量类型标记
- API 运行中状态、异常中断与重试机制
- Web 与 API 报告统一编号和导出

### P1：团队协作

- 项目成员与角色权限
- 用例版本、变更记录和评审流程
- 标签、模块、负责人和批量操作
- 缺陷关联与 Jira/Confluence 集成

### P2：持续质量

- 定时任务、Webhook 和 CI 触发
- 趋势报表、失败聚类与不稳定用例识别
- 数据驱动、参数化和 Mock 服务
- 多阶段测试环境与发布门禁
